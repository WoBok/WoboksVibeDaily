# 分类 Inbox 文章

## 原则

- 先完整阅读文章，再依据核心主题、用途和已有分类判断归属；不要只看标题或标签。
- 优先复用语义足够贴合的现有叶子分类。只有现有分类明显无法容纳、且新分类预计可持续收纳同类文章时，才建议新建分类。
- 将直接包含文章的文件夹视为终止分类的叶子文件夹：可以继续放入同类文章，但不得在其中创建子分类。
- 新分类必须是叶子文件夹，并放在不直接包含文章的现有分类分支下。目录名必须沿用同级分类的 `0x<编号> - <名称>` 格式，以 `0x` 开头并使用下一个可用编号；不得重排或修改已有分类编号。
- 不因单篇文章的细小差异创建过窄分类，不预先建立空泛或未经需要证明的层级。
- 将文章及其依赖视为一个移动单元：包括正文实际引用的 `assets` 资源，以及与文章对应的 `code - <文章名>` 代码浏览模板文件夹。
- 未经用户确认，不移动文件、不创建目录，也不顺带修改文章内容或元数据。

## 工作流

### 1. 调查

1. 确认待分类文章和分类根目录；排除 Inbox 自身、资源目录、隐藏目录及非分类目录。
2. 读取文章全文。
3. 解析文章对 `assets` 文件夹中本地资源的引用，并确认每个源文件存在。若存在与文章主文件名对应的 `code - <文章名>` 文件夹，将其识别为配套代码浏览模板。
4. 列出分类树，识别已有叶子文件夹。结合目录名、其中已有文章的文件名和必要的正文抽样，判断每个候选分类的实际范围。
5. 比较最贴近的已有叶子分类，避免仅凭关键词匹配。

### 2. 建议

默认只给出一个首选建议：

- **复用已有分类**：给出文章、目标叶子文件夹及简短理由。
- **创建新分类**：给出包含 `0x` 编号的完整叶子文件夹名称、完整父路径、现有分类不合适的原因，以及新分类为何确有必要。

同时列出将伴随文章移动的引用资源或代码模板文件夹。只有两个方案确实难以取舍时才列出备选。明确说明此阶段尚未进行任何文件操作，并等待用户确认。

### 3. 执行

- 用户确认建议后，重新确认源文件存在、目标路径仍符合叶子规则，且文章、资源和代码模板均不会覆盖同名文件，然后只执行已确认的创建和移动操作。
- 用户一开始就明确指定唯一、已存在的目标叶子分类时，无需再次确认，核验后直接移动。
- 用户明确要求“创建某分类并移动”时，可按其指令直接执行；仍须遵守叶子规则。
- 创建分类前检查同级目录的现有编号，采用下一个可用的 `0x` 编号；若编号冲突或同级命名规则无法确定，先请求用户确认。
- 对普通文章，只移动正文实际引用的 `assets` 资源，并在目标叶子文件夹内保留其 `assets/...` 相对路径；不要移动无关资源或整个共享 `assets` 文件夹。
- 对带有 `code - <文章名>` 配套目录的代码浏览模板，将文章和该目录整体移动到目标叶子文件夹，不得拆分或遗漏目录内容。
- 移动资源前检查它是否还被 Inbox 中的其他文章引用；若存在共享引用，先说明风险并请求用户决定，不得直接移动导致其他文章失效。
- 目标名称含糊、目标不存在、目标不是叶子文件夹，或会发生覆盖时，不要猜测或改名；先向用户说明问题并请求确认。
- 执行后报告文章、伴随资源和代码模板的新路径，以及实际创建的分类文件夹；没有创建时明确说明复用了现有分类。
