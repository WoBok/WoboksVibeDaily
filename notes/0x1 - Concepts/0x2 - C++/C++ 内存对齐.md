## 什么是内存对齐？

**内存对齐（Memory Alignment）** 是编译器为了让 CPU 更高效地读取数据，按照特定规则将变量的起始地址安排在某个整数倍地址（通常是 2、4、8、16 字节）上的机制。

在 C++ 中，结构体或类所占用的内存大小往往并不等于各个成员大小的直接累加，中间可能会被编译器填充（Padding）空白字节。

---

## 一、 为什么要做内存对齐？

### 1. 硬件层面的性能优化

现代 CPU 读取内存并不是按单字节逐个读取，而是以 **字长（Word Size，如 4 字节或 8 字节）为粒度的块（Memory Granularity）** 批量读取。

假设 CPU 每次读取 4 个字节，内存地址以 4 的倍数对齐（0x00, 0x04, 0x08...）：

* **已对齐（地址 0x04 存放一个 4 字节 int）**：CPU 只需发起 **1 次** 内存访问即可取走完整数据。
* **未对齐（地址 0x01 存放一个 4 字节 int）**：
* 第 1 次读取：读取 `0x00 ~ 0x03`（获取高 3 字节）；
* 第 2 次读取：读取 `0x04 ~ 0x07`（获取低 1 字节）；
* 额外开销：CPU 还需通过移位（Shift）和掩码（Mask）将两块数据拼装在一起。



```
【未对齐访问 (读取 0x01~0x04 的 int)】
Memory: [0x00] [0x01] [0x02] [0x03] | [0x04] [0x05] [0x06] [0x07]
               \________  ________/    \___  ___/
                        \/                 \/
            [ 第 1 次读取 (0x00-0x03) ]  [ 第 2 次读取 (0x04-0x07) ]
                         \                 /
                          ->   移位拼接   <- (极大消耗 CPU 时钟周期)
```

### 2. 硬件架构的兼容性

某些精简指令集架构（如部分 ARM、MIPS、SPARC）不支持未对齐的内存访问。若强行访问未对齐地址，硬件会直接触发 **硬件异常（Bus Error / Alignment Fault）** 导致程序崩溃。

## 二、 内存对齐的底层规则

结构体内存布局遵循以下 **三大核心规则**：

1. **成员自身对齐规则**：每个成员的起始地址，必须是其自身对齐模数（`alignof(Type)`）的整数倍。
2. **结构体整体对齐规则**：结构体的总大小必须是其 **内部最大成员对齐模数**（或通过 `#pragma pack` 指定的模数）的整数倍。如果不够，末尾会自动填充 Padding。
3. **嵌套结构体规则**：如果结构体内包含子结构体，子结构体按其内部最大基础成员的大小进行对齐。

## 三、 实例与图示剖析

### 案例 1：典型结构体对齐分析

```cpp
struct Example {
    char a;    // 1 byte
    int b;     // 4 bytes
    short c;   // 2 bytes
};
```

各成员按规则排布如下：

```
[字节偏移]  0x00    0x01    0x02    0x03    0x04    0x05    0x06    0x07    0x08    0x09    0x0A    0x0B
           +-------+-------+-------+-------+-------+-------+-------+-------+-------+-------+-------+-------+
[内存布局]  | char a| [Pad]   [Pad]   [Pad] |          int b                |    short c    | [Pad]   [Pad] |
           +-------+-------+-------+-------+-------+-------+-------+-------+-------+-------+-------+-------+
说明:
- char a   占 1 字节 (偏移 0)。
- int b    需要 4 字节对齐，故偏移 1~3 填充 3 字节 Padding，b 位于偏移 4~7。
- short c  需要 2 字节对齐，位于偏移 8~9。
- 整体大小  最大成员为 int(4 字节)，当前已用 10 字节，需补齐到 4 的倍数 -> 末尾填充 2 字节。
- 总大小   12 字节（而非 1 + 4 + 2 = 7 字节）。
```

---

### 案例 2：通过调整成员顺序优化内存

只需改变结构体成员的声明顺序（从大到小排列），即可消除大部分填充碎片：

```cpp
struct OptimizedExample {
    int b;     // 4 bytes (偏移 0~3)
    short c;   // 2 bytes (偏移 4~5)
    char a;    // 1 byte  (偏移 6)
               // 末尾 Padding 1 字节 (对齐到 4 的倍数)
};             // 总大小：8 字节 (相比 12 字节节省了 33% 空间)
```

```
[字节偏移]  0x00    0x01    0x02    0x03    0x04    0x05    0x06    0x07
           +-------+-------+-------+-------+-------+-------+-------+-------+
[内存布局]  |          int b                |   short c     | char a| [Pad] |
           +-------+-------+-------+-------+-------+-------+-------+-------+
```

## 四、 C++ 控制与查询对齐

### 1. alignof、sizeof 与 alignas (C++11)

* `alignof(Type)`：查询类型或对象的对齐要求（返回 `size_t`）。
* `sizeof(Type)`：查询类型或对象实际占用的总内存大小（以字节为单位，包含 Padding）。
* `alignas(N)`：强制指定变量或类型的对齐方式（$N$ 必须是 2 的整数次幂，且不能小于默认对齐要求）。

```cpp
#include <iostream>

// 正常情况下 3 个 float 为 12 字节，但通过 alignas(16) 强制要求按 16 字节对齐（常用于 SIMD 指令加速）
struct alignas(16) FastVector {
    float x, y, z; 
};

int main() {
    std::cout << "alignof(FastVector): " << alignof(FastVector) << "\n"; // 输出 16
    std::cout << "sizeof(FastVector): "  << sizeof(FastVector)  << "\n"; // 输出 16（自动填充 4 字节以满足 16 的倍数）
}
```

### 2. #pragma pack（预处理指令）

用于改变编译器的默认对齐模数，取消或减少内部填充，常用于网络通信协议包或二进制文件解析：

```cpp
#include <iostream>

#pragma pack(push, 1) // 设置 1 字节对齐（取消所有填充）
struct PacketHeader {
    char type;    // 1 字节
    int length;   // 4 字节（紧随其后，不填充 3 字节）
};
#pragma pack(pop)     // 恢复默认对齐

int main() {
    std::cout << "sizeof(PacketHeader): " << sizeof(PacketHeader) << "\n"; // 输出 5 字节（若不加 pack 则为 8 字节）
}
```

> **注意：** 使用 `#pragma pack(1)` 虽能节省空间并精确匹配外部数据流格式，但会引发未对齐访问，降低 CPU 存取性能，在部分硬件架构上还可能触发硬件异常。

---

> **内存对齐是以空间换时间的硬件适配机制：通过在变量间填充空白，使数据地址对齐到 CPU 访问字长的整数倍，从而保证单次指令即可完成读取并避免硬件异常。**
