① 什么是 FRAGMENT

一句话定义：片元是「准备写入某个像素的一份完整数据包」

Fragment（片元）是光栅化的产物：三角形覆盖到哪个像素位置，GPU 就在那里生成一个片元， 打包好该位置的全部信息——插值颜色、深度 z、纹理坐标 UV、法线…… 但它还不是像素：要先通过模板、深度等层层测试，再经混合写入帧缓冲，才成为屏幕上那个像素。

🎯 一个类比：像素是「岗位」，片元是「候选人」

岗

像素 Pixel = 一个编制岗位

帧缓冲里的一个存储格子，对应屏幕上一个发光点。一个格子只存一个颜色值，谁来坐得竞争。

选

片元 Fragment = 候选人

每个被三角形覆盖的像素位置产出一位候选人，带着简历（颜色 / 深度 / UV / 法线）进入后续流程。

试

测试 Tests = 层层面试

裁剪测试、模板测试、深度测试逐轮淘汰；着色器里一句 discard 还能当场弃权。

聘

写入 & 混合 = 上岗

过关的片元才能写入：不透明直接覆盖；半透明与格子里的旧值Alpha 混合。

关键认知：一个像素位置可能收到 0 个、1 个、甚至 N 个片元（多个三角形重叠于此）， 但最终只有一个结果写进去。所以——片元是过程数据，像素是最终存储。
② 渲染管线中的位置

片元在流水线的哪一站「诞生」？

顶点着色器处理顶点，帧缓冲存像素。连接两者的光栅化（Rasterization），正是片元的诞生地。

▲ 上行以顶点为单位，下行以片元为单位；分界线就是光栅化
Early-Z 只是优化，不改变结果。硬件把深度 / 模板测试提到着色之前，让注定被遮挡的片元根本不进片元着色器。 但只要着色器里出现 discard 或写 gl_FragDepth，片元的存亡与深度就得等着色算完才知道—— 此时硬件自动退回 Late-Z，把测试放回着色之后。

④ 动手演示 · 片元争夺战（深度测试）

一个像素，两个候选人：谁上岗？

两个三角形前后交叠，按 A → B 的顺序绘制：A 橙色在前（z=0.30）、B 绿色在后（z=0.60）。 重叠区的每个像素都会收到两个片元。开启「深度测试」，GPU 淘汰更远的那个；关掉它，后画的直接覆盖。 点击任意像素，右侧回放它的「面试记录」。

▲ 每小格 = 1 个像素（中心点 = 覆盖采样点）· ● 圆 = A 片元 · ■ 方 = B 片元 · 点击任意像素查看它的面试记录
数一数：重叠区有 N 个像素，却生成了 2N 个片元——这就是「片元 ≠ 像素」最直观的证据。 开深度测试，多出的 N 个片元被淘汰；关掉，它们写进去又被覆盖。两种情况都白干了 N 份活， 这就是性能杀手 Overdraw：算了，没用上。
⑤ 动手演示 · MSAA 放大镜

进阶一层：片元是「像素级」的，采样点才是「亚像素级」的

开启 4×MSAA 后，每个像素内部有 4 个采样点。关键是：GPU 仍然只生成一个片元， 颜色只算一次（默认在像素中心求值），但这个片元带着一张覆盖掩码，记录 4 个采样点里哪几个落在三角形内。 解析（resolve）时把 4 个采样点平均，就得到最终像素色。拖动滑块改变边缘的角度与位置，观察掩码与像素色的变化。

▲ 一个像素被放大：4 个采样点（按 D3D 标准 4×MSAA 旋转网格位置绘制），实心 = 被三角形覆盖

📐 真实硬件的采样位置不是均匀的 2×2 网格。D3D 标准 4×MSAA 用旋转网格：(3/8, 1/8)、(7/8, 3/8)、(1/8, 5/8)、(5/8, 7/8)——全是 1/16 的奇数倍。 这样 x、y 方向各有 4 个互不相同的坐标，接近水平 / 垂直的边缘也能分出 5 级灰阶；均匀 2×2 网格在这类边缘上只有 3 级（0 / 50% / 100%）。 OpenGL 的位置由厂商自定，可用 glGetMultisamplefv(GL_SAMPLE_POSITION) 查询。上方演示已按 D3D 真实位置绘制。
再看一遍数量关系：无 MSAA 时，一个像素位置 = 0 或 1 个片元；4×MSAA 时仍是 1 个片元， 只是内部分成 4 个采样点各自记色。「采样点」才是比像素更细的单位，片元始终挂在像素这一级。
补充：像素中心若落在三角形外，默认插值会外推出越界的属性值；此时用 centroid 限定符把求值点拉回覆盖区域内即可。
⑥ FRAGMENT vs PIXEL

三个演示之后，六个维度收个尾

维度🧩 Fragment 片元🖥️ Pixel 像素
本质 流水线里的一份数据包 / 中间产物（坐标 + 插值属性） 帧缓冲里的一个存储单元，对应屏幕上的发光点
出身 由光栅化现场生成——三角形覆盖到哪，就在哪生成一个 由渲染目标分辨率决定，绘制前就已存在：1920×1080 = 2,073,600 个
数量关系 一个像素位置对应 0 / 1 / N 个片元（重叠图元、半透明叠加） 每个像素位永远只存一个最终颜色值
生死 随时可能「死亡」：被 discard 或模板 / 深度测试淘汰 → 像素保持不变 始终存在；无片元写入时保持旧值（或清屏色）
携带信息 屏幕坐标、深度 z、插值颜色、UV、法线、覆盖掩码…… 最终 RGBA 颜色（深度 / 模板在各自缓冲的对应格）
谁处理它 片元着色器（Fragment Shader，D3D 里叫 Pixel Shader） 显示控制器扫描帧缓冲，驱动物理像素发光
为什么 OpenGL 叫 Fragment Shader，DirectX 叫 Pixel Shader？ 两者指同一个阶段。D3D 沿用「处理的多半就是最终像素」的习惯叫法；OpenGL 的命名更严谨—— 多重采样、深度剔除、discard 之下，着色器处理的对象未必会成为像素。
⑦ 代码里的片元长什么样

一段最真实的片元着色器（GLSL）

片元着色器的每一个 in 变量，都是光栅化为本片元插值好的；它输出的，是这个候选人想写入像素的颜色。

// ========== 片元着色器：每个片元跑一次 ==========
in vec3 vColor;   // ← 光栅化用重心坐标插值出的「本位置」颜色
in vec2 vUV;      // ← 插值出的纹理坐标
in float vDepth; // ← 插值出的深度（也可读 gl_FragCoord.z）

uniform sampler2D uTexture;
out vec4 FragColor;

void main() {
    vec4 tex = texture(uTexture, vUV);
    if (tex.a < 0.1) discard;      // ✂ 这个片元就地「自杀」：像素保持不变！
    FragColor = vec4(tex.rgb * vColor, tex.a);
    // ↑ 注意：这里只是「提交申请」。后面还有模板测试、
    //   深度测试、Alpha 混合，层层过关后才真正写入像素。
}
⑧ 常见误区 & 一分钟速记

把最后几个坑填平

❓ 片元就是像素吗？为什么很多教程混着叫？

不是。最简单的情况下（无 MSAA、无重叠、不透明），一个像素恰好收到一个片元且必然写入，两者 1:1，所以口头上常混用。 但只要涉及重叠图元、半透明、深度剔除、discard、多重采样，这个 1:1 立刻破裂——演示 ④⑤ 已经让你亲眼看到。

❓ 片元着色器为什么比顶点着色器贵那么多？

量级差得远。一个三角形只有 3 个顶点，却可能覆盖几十万个像素，也就是几十万个片元，每个都要跑一遍着色器。 而且 GPU 以 2×2 的 Quad 为单位调度片元（纹理 mipmap 需要相邻像素的导数）， 三角形边缘凑不满一个 Quad 时，补上的 helper 片元照算不误、算完丢弃。 所以「减少 Overdraw」「避免过密的小三角形」「用 Early-Z 提前剔除」都是重要优化方向。

❓ 半透明物体为什么要从远到近排序绘制？

因为 Alpha 混合不满足交换律：同一个像素，片元到达顺序不同，混合结果就不同。 而且半透明片元通常只写颜色不写深度，深度测试帮不上忙，先后次序全靠 CPU 侧排序保证。

❓ UE5 / 引擎里哪里能直接看到「片元」的影子？

材质编辑器最终编译出来的就是 Pixel Shader：Opacity Mask 对应 discard， Pixel Depth Offset 直接改片元深度。视图模式里的 Quad Overdraw / Shader Complexity 热力图， 本质就是「每个像素被多少片元反复处理」的可视化。
