01变量名是什么？

int a = 10; 里的 a 代表一个地址吗？不——这是要打磨的第一个直觉。

这行代码涉及三个东西：对象（一块存着值 10 的内存）、名字（a，访问它的入口）、地址（这块内存的位置，要用 &a 才能拿到）。

一个比喻

"张三住在北京路 8 号"——张三不是"北京路 8 号"。a 是那个人，地址是门牌号。用 a 操作的是值；用 &a 才拿到地址。

编译之后：名字被彻底擦除

变量名是编译期的概念。编译器维护一张符号表（名字 → 类型、作用域、存储位置），每个使用 a 的地方经查表后被替换成机器层面的定位方式：

替换结果什么时候发生
栈偏移，如 [rbp-4]最常见，局部变量的读写
寄存器被优化时——变量全程不进内存，此时它根本没有地址
立即数（常量）编译期能确定值时，直接常量折叠
要点

变量名 = 一个对象的名字；编译后，每个变量名都变成"那块存储的定位方式"（栈偏移 / 寄存器 / 常量）。可执行文件里没有 "a" 的任何痕迹。至于那块存储里装的是数值还是地址，由变量的类型决定——指针只是"内容恰好是地址"的普通变量。

02栈与堆：对象被分配到哪？

决定对象在栈还是堆的，不是类型，而是创建方式。

class Student {
public:
    int   id;     // 4 字节
    float score;  // 4 字节
};

void func() {
    Student s1;                  // 栈上：局部变量，不管什么类型都在栈上
    Student* s2 = new Student(); // s2 在栈上；它指向的对象才在堆上
}

规则只有一句话：new 出来的才在堆上。其余局部变量（包括 class 对象）都在栈上；全局/静态变量在静态区。

Student s1; 已经按类的结构划分好内存了吗？

是的，而且"怎么划分"在编译期就算好了。编译器看到类定义就画出了"户型图"：

Student 的内存布局（sizeof = 8 字节） ┌──────────────┬──────────────┐ │ id (偏移+0)│ score(偏移+4)│ └──────────────┴──────────────┘

进入函数时，一条 sub rsp, N 指令一次性为所有局部变量腾出栈空间，随后调用构造函数——分配和构造在声明那一行就完成了。之后 s1.id = 10; 编译成 mov DWORD PTR [rbp-8], 10：对象名变成栈基址，成员名变成固定偏移，名字全部消失。注意：类没写构造函数时成员是垃圾值，划分 ≠ 初始化。

Student s1;（自动存储期）new Student()（动态存储期）
得到什么一个对象（类型 Student）一个指针（类型 Student*）
分配成本一次栈指针减法，几乎为零堆管理算法的真实开销
何时释放离开作用域自动析构回收必须 delete，否则泄漏

所以 Student s1 = new Student(); 编译不过——右边返回的是指针，类型对不上。用 new 就要用指针接，成员访问用 s2->id（*s2.id 是优先级陷阱：. 比 * 先算）。

指针自己住在哪？它能指向哪？

int a = 10;              // 栈
int* p1 = &a;          // ✅ 指针存【栈】地址，完全合法，极其常见
int* p2 = new int(20); // ✅ 存【堆】地址

但指向栈地址有个致命陷阱——栈对象活不过作用域：

int* bad() {
    int x = 42;
    return &x;     // ❌ 函数结束 x 销毁，指针指向已回收的栈内存 → 悬空指针
}

这正是堆存在的核心理由：栈对象"活不过作用域"，堆对象"活到你 delete 为止"。想让对象在函数返回后还活着，就必须放堆上。

03引用：给同一个对象起第二个名字

T& 不创建任何新对象——这是它和"赋值给新变量"最根本的区别。

Student s1;        // 创建一个真实对象
Student& s2 = s1;  // 没有新对象！s2 只是 s1 的别名
Student s3 = s2;   // 新对象！调用拷贝构造函数

两行长得很像的代码，其实是两个操作：

Student s3 = s2;   // s3 还不存在 → 拷贝【构造】函数  Student(const Student&)

Student s3;
s3 = s2;             // s3 已存在   → 拷贝【赋值】运算符 operator=(const Student&)
两个补充

① 默认拷贝是浅拷贝：类里有指针成员时，默认只复制指针的值，两个对象指向同一块内存；想各有一份（深拷贝）要自己写拷贝构造。
② 从 C# 来的读者注意：C# 的 Student s2 = s1;（class）复制的是引用，还是同一个对象；C++ 同样写法是复制对象本身。C# class 默认引用语义，C++ class 默认值语义——C# 的 class 变量更像 C++ 的指针/引用。

三种引用：能绑定什么，想表达什么

类型能绑定左值能绑定右值意图
T&（左值引用）✅❌借来用，可能修改它
const T&✅✅只读，不复制（const 是特例，可绑定右值）
T&&（右值引用）❌（除非 std::move）✅这个对象可被消耗、搬空——第 6 章详解
int a = 10;
int&  r1 = a;             // ✅
int&  r2 = 42;            // ❌ 左值引用不能绑定右值
const int& r3 = 42;      // ✅ const 特例
int&& r4 = 42;           // ✅ 右值引用绑定右值
int&& r5 = a;            // ❌ a 可能还要继续用，不能当成可消耗对象
int&& r6 = std::move(a); // ✅ 你明确保证了

（左右值的定义下一章才登场，这里先记住绑定规则的样子即可。）

04机器世界里，"位置"和"数据"是两回事

左值右值不是拍脑袋的语法分类，而是被计算机的工作方式逼出来的。

任何程序跑起来，CPU 只面对两种东西：存储位置（内存单元、寄存器，每个位置有地址，内容可改写）和数据（计算的结果，躺在寄存器里，随时被覆盖）。看 c = a + b 编译后的样子：

load  r1, [a的地址]    ; 从"位置"取出"数据"
load  r2, [b的地址]
add   r1, r1, r2       ; 新数据诞生——但只在寄存器里，没有"家"
store [c的地址], r1    ; 写回某个"位置"

第三行是关键：a + b 的结果存在，但没有对应的内存位置。硬件层面"位置"与"值"天然分离。

于是赋值语句制造了矛盾：c = a + b 合法，a + b = c 荒谬——左边需要一个位置（生成 store 必须知道往哪写），右边只需要数据。编译器必须有概念来区分"能提供位置的表达式"和"只能提供数据的表达式"。

05左值与右值：核心判据

左值/右值是表达式求值结果的属性，与表达式长什么样无关。

本质判据

求值结果是一个有身份、可回访的对象（表达式结束后它还在原地），还是一团转瞬即逝的纯数据（算完就消散）？前者是左值，后者是右值。操作判据：对它取地址 &expr，合法 → 左值；报错 → 右值。

误解一：左值 = 变量名，右值 = 复杂表达式？

变量名确实几乎总是左值，纯计算确实总是右值——但这是巧合，不是定义：

arr[1] = 99;     // 带下标的运算式，但结果是数组里那个固定的格子 → 左值
*p = 88;         // 解引用运算式，结果指向真实对象 → 左值

int b = std::move(a);   // 只用了变量名 a，但整个表达式是右值

误解二：按等号左右区分？

等号左右不是两种表达式的分类，而是同一表达式可能处的两种使用语境：

arr[0] = arr[1];   // 左边用它的"位置"（写入），右边用它的"值"（读出）——两个都是左值
int b = a;        // a 是左值，照样待在右边（读出值来用）

误解三：和栈/堆混在一起

栈/堆是"对象住在哪"，左值/右值是"表达式结果有没有身份"——两套正交的分类，四个象限都有东西：

左值（有身份的对象）右值（临时的值）
栈int a = 10; 的 aa + b 的临时结果；函数按值返回的临时对象
堆*p（new 出来的那个对象）堆内存本身不会以右值的身份被访问到；但 new 返回的指针值是右值
疑问：字符串相加，不会在堆上开辟内存存中间结果吗？

会！a + b 求值时，确实构造了一个临时 string 对象：壳在栈上（指针+长度），并在堆上新申请一块字符缓冲（肉）。这并不和"堆上没有右值对象"矛盾，因为这是两个层面的事：

· "a+b 是右值"——描述的是这个临时对象整体作为表达式结果的命运：用完即弃。壳在栈上、肉在堆上，都不妨碍它整体是右值；

· "堆上没有右值对象"——说的是访问堆内存的方式：堆内存只能通过 *p、p[i] 摸到，而解引用的结果永远是左值。仓库里的货没有"临时"属性，但货的主人可以是个临时对象。

正是"右值经常拥有堆资源"这个组合，构成了下一章移动语义要解决的场景。

要点：*p 是左值

new 表达式的结果（指针值）是右值——不接住就丢失。但 *p 的结果是堆上那个确定的对象：有稳定位置、可反复回访、能放等号左边、能取地址——它是左值。表达式是访问对象的通道，对象是通道尽头的东西；通道用完就拆，东西一直在那。

06移动语义：不再复制，直接接管

右值引用是被一场性能灾难逼出来的。这次我们造一个简化版字符串类，把每一步摆在台面上。

先看痛在哪里

资源类对象都是"壳肉分离"：壳在栈上（指针+长度），肉在堆上（字符缓冲）。在 C++11 之前：

std::string c = a + b; 临时对象：malloc 一块堆内存 → 拷贝数据进去 ↓ 拷贝进 c：c 再 malloc 一块堆内存 → 再逐字符复制一遍 ↓ 临时对象析构：free 掉它的堆内存 ← 刚建好、原样抄完、立刻扔掉

临时对象反正用完即弃，为什么不能把它的堆内存直接过户给 c？能，但编译器不敢——它无法区分"用完即弃的临时对象"和"后面还要用的变量"。如果偷了 a 的内存，a 就废了。C++11 的解法：给"可消耗对象"一个类型系统层面的身份——右值引用 T&&，再配一个专门接收它的构造函数。

自己动手：一个支持移动的字符串类

class MyString {
public:
    char* data = nullptr;   // 指向堆上的字符缓冲（肉）
    int   len  = 0;

    // ① 普通构造：申请堆内存，填入内容
    MyString(const char* s) {
        len  = strlen(s);
        data = new char[len + 1];
        strcpy(data, s);
    }

    // ② 拷贝构造：源对象还要用 → 老实深拷贝
    MyString(const MyString& other) {
        len  = other.len;
        data = new char[len + 1];   // 再 malloc 一块
        strcpy(data, other.data);   // 逐字符复制，贵
    }

    // ③ 移动构造：源对象可消耗 → 偷走指针
    MyString(MyString&& other) noexcept {
        data = other.data;          // 1. 接管堆内存（抄地址，O(1)）
        len  = other.len;
        other.data = nullptr;       // 2. 源置空：所有权易主
        other.len  = 0;
    }

    // ④ 析构：释放自己拥有的堆内存
    ~MyString() { delete[] data; }
};

移动构造的四行，行行关键：没有 new、没有 strcpy，只把对方指针里的地址抄过来，两个指针暂时指向同一块堆内存；然后 other.data = nullptr——这一步是生命线。少了它，两个对象都以为自己拥有这块内存，析构时 delete 两次（double free，程序崩溃）。置空后，源对象析构执行的是 delete nullptr（安全的空操作）：所有权完成过户，每块堆内存恰好被释放一次。

编译器怎么决定用 ② 还是 ③？

看初始化用的表达式是左值还是右值，T& 与 T&& 的绑定规则就是调度开关：

MyString a("Hello");

MyString b = a;                  // a 是左值（有名字，还要用）
                                 // → T&& 拒绝绑定 → 选中② 拷贝构造，深拷贝，安全

MyString c = MyString("World"); // 临时对象是右值（用完即弃）
                                 // → T&& 精确匹配 → 选中③ 移动构造，接管，高效
理解 move 最重要的一句话

move 不是把数据搬家，而是把"资源的控制权"转交出去：指针过户 + 源置空。只要源对象还有名字、还可能被使用，编译器就绝不敢偷；只有可消耗的临时对象才会被送上移动构造的手术台。

07std::move：只是标记，不是搬运

这个名字很有误导性——std::move 本身不移动任何东西。

实现原理：一次 static_cast

还剩一个问题：有名字的对象（左值），如果我确定后面不用它了，怎么让它也走移动构造？std::move 就是这张"许可证"。它的实现简单到令人失望：

// std::move 的本质（简化版实现）
template <typename T>
remove_reference_t<T>&& move(T&& arg) {
    return static_cast<remove_reference_t<T>&&>(arg);   // 就这一行
}

它做的唯一一件事：把表达式强制转换成 T&& 类型。而"一个表达式是 T&& 类型"在 C++ 里就意味着"这个表达式是右值"。完整链条：

std::move(a) ↓ static_cast，表达式类型变成 MyString&& ↓ 表达式变成右值 ↓ 重载决议：MyString&& 能绑定了 → 选中移动构造 ↓ 移动构造执行：抄指针、置空 ↓ 资源过户完成

std::move 只参与前两步——贴标签。真正动手的是移动构造函数。它真正说的话是："我保证 a 接下来可以被当成可消耗对象，我允许你搬空它。"

最容易混淆的两行代码

MyString&& r = std::move(a);  // r 是【引用】：没有新对象，没有移动，r 和 a 是同一个对象
MyString    b = std::move(a);  // b 是【新对象】：调用移动构造，这才真的"搬"

验证：&a != &b（两个独立对象，析构各跑一次）；而第一行的 r 只是别名，std::move 在那里白写了。右值引用本身只是引用；"移动"是用这个右值去构造/赋值另一个对象时才发生。

完整运行一遍（带监控打印）

int main() {
    MyString a("Hello");
    MyString b = a;            // 左值 → 拷贝构造
    MyString c = std::move(a); // 右值 → 移动构造
}

// 输出（地址是示意）：
// 构造     a    数据@0x1000
// 拷贝构造 b    新@0x2000 ← 复制自 0x1000   （新 malloc + 逐字符复制）
// 移动构造 c    接管 0x1000               （没有新 malloc！）
// 析构     c    data=0x1000   ← c 释放接管来的内存
// 析构     b    data=0x2000   ← b 释放自己拷贝来的内存
// 析构     a    data=nullptr  ← 被搬空但合法存在，delete nullptr 无害

对账三个关键点：① 同一个 a，加不加 move 决定了走拷贝还是移动；② a 析构时 data=nullptr——移动构造里那句置空的救命作用；③ 每块堆内存恰好释放一次，所有权全程有且只有一个主人。move 之后的 a 处于有效但未指定状态：可以析构、可以重新赋值，但别依赖它的旧内容。

最反直觉的一点：T&& 类型的变量，本身是左值

void foo(MyString&& s) {
    bar(s);            // 传给 bar 的 s ……是左值！
    bar(std::move(s)); // 想继续当"可消耗对象"传，必须再 move 一次
}

s 的类型写着 MyString&&，但表达式 s 是左值。原因很简单：s 有名字了——有名字 → 有身份 → 能取地址 → 符合左值的全部定义。

把两个概念分开

T& / T&& 是引用类型（变量的类型）；左值 / 右值是表达式的属性。"右值引用"说的是它能绑定什么，不是它自己是什么。所以右值层层传递时，每一层都要重新 std::move（模板里配合 std::forward 即"完美转发"）。

每种类型都有移动构造吗？

情况移动构造从哪来
内置类型（int、double、指针）没有资源可偷，move 就是 copy
类里没写析构/拷贝/移动任何函数✅ 编译器自动生成：逐个成员 move
你写了析构或拷贝❌ 编译器不生成——std::move 会静默退化成拷贝（右值绑定到 const T&）
成员全是 string/vector/unique_ptr什么都不用写（零法则），默认移动就正确高效
自己用裸指针/new 管资源必须按"五法则"自己写全，或改用智能指针
两个使用禁忌

① 不要写 return std::move(local);——会阻止编译器的返回值优化（RVO），反而变慢。
② move 后不要再依赖原对象的旧内容。

08收尾：一页心智模型

如果整篇只能记住一屏，就记这个。

变量名
对象的名字（不是地址）。编译后消失，替换成栈偏移 / 寄存器 / 常量。
栈 / 堆
对象的住址，由创建方式决定（new 与否）。声明即分配并构造；栈自动回收，堆手动 delete。
引用
别名，不创建新对象。Student s3 = s2; 才会拷贝构造出一个新对象。
左值
求值结果是有身份、可回访的对象——表达式结束它还在，能取地址、能写入。
右值
求值结果是用完即弃的临时值——算完就消散，可被消耗。
T&
绑定左值。"借来用，可能改。"
const T&
左右值都能绑。"只看看，不复制，也不改。"
T&&
绑定可消耗对象。"可以把它搬空。"
移动语义
搬的不是数据，是资源的所有权：指针过户 + 源置空。内存本身一字节未动。
std::move(x)
一次 static_cast："我允许你把 x 当成可消耗对象。"它不移动任何东西。
T&& 变量
一旦有了名字，它自己就是左值——继续传递要再 move。
三套正交
栈/堆（住址）、左值/右值（结果有无身份）、等号左右（使用语境），两两互不等价。
最后的因果链

因为机器世界里"位置"和"数据"是两回事，所以语言必须区分"指向位置的表达式"（左值）和"只产出数据的表达式"（右值）；后来又因为"临时结果背后可能藏着昂贵的资源，值得搬移而不是复制"，这个区分从"管能不能赋值"升级成了"管能不能偷资源"的性能优化基础设施。你看到的每一条规则——能取地址的是左值、右值引用用来接管资源、std::move 只是个标记——都不是规则本身，而是这条因果链长出来的枝叶。
