PCFPercentage-Closer Filtering阴影贴图的百分比渐近过滤

1阴影贴图是怎么判定阴影的

1.1 阴影贴图的基本流程

阴影贴图（Shadow Map）算法由两个阶段组成：

  1. 从光源看场景，只写深度。得到一张纹理，每个 texel 对应从光源射出的一条光线，存的是这条光线碰到的第一个表面离光源有多远，记作 z。光线被遮挡物挡住，存的就是遮挡物的深度；没有东西挡、一路照到地面，存的就是地面的深度。
  2. 从相机渲染时，对每个要着色的点 p，把它变换到光源空间（见 1.2），得到它在阴影贴图上的 UV 和它自己到光源的深度 d_p。然后查表比较：
\mathrm{lit}(p) = \begin{cases} 1 & d_p \le z(uv) \\ 0 & d_p > z(uv) \end{cases}

也就是：如果 p 比“光源在这个方向上看到的第一个表面”还远，说明中间有东西挡着，p 在阴影里。

这一步本质上是一个阶跃函数（Heaviside）：输出只有 0 或 1。

1.2 光源空间与它的原点

“光源空间”就是从光源看出去的那台虚拟相机的观察空间：朝向是光的方向，投影方式取决于光源类型，原点放在哪里也按光源类型来定。点光源、聚光灯本身有位置，原点就在灯上；方向光只有方向没有位置，沿光方向平移原点不会改变正交投影的结果，所以原点可以放在任何方便的地方，一般放在需要覆盖阴影的区域中心。

阴影类型投影方式光源空间原点
聚光灯透视灯的位置
点光源透视（立方体 6 个面各一个视锥）灯的位置，6 个面共用
面光源（如矩形光）透视灯的位置
方向光·整场景 / 级联阴影正交每一级联要覆盖的区域中心（通常是该级联包围球的球心），并对齐到 texel 网格
方向光·逐物体阴影正交被投影物体包围盒的中心
局部光·逐物体阴影透视灯的位置；灯离物体太近时沿光线往后推，让物体能放进视锥

关于原点的选取，有以下几点说明：

  • 方向光的原点在区域中间，而不是“光那一头”。站在原点与光源之间的遮挡物在光源空间里深度为负，所以方向光的深度范围通常会朝光源方向拉得很远，让远处的山体也能投下阴影。
  • 对齐到 texel 网格：相机移动时级联区域跟着动，如果原点以非整 texel 的量移动，每个 texel 覆盖的世界位置就会变，阴影边缘会闪烁（shimmering）。把原点在阴影贴图空间里吸附到 texel 的整数倍即可消除。
  • 为什么不直接用世界原点：先把世界坐标平移到以光源空间原点为中心，坐标就都是“相对原点的小数值”，在大世界中远离世界原点时也不会丢浮点精度。

1.3 采样点：连续的坐标，离散的格子

变换到光源空间后得到的 UV 是 0~1 之间的连续值。把它乘以阴影贴图分辨率，就得到以 texel 为单位的坐标。例如分辨率 1024、u = 0.005176，则

u_{\text{texel}} = 0.005176 \times 1024 \approx 5.3

这个位置称为采样点。把阴影贴图想象成一张方格纸，采样点就是纸上的一个小圆点，它可以落在格子里的任何位置：

  • 整数部分 5：采样点落在第 5 号 texel 里（本文约定第 k 号 texel 占据区间 [k,\ k+1)）；
  • 小数部分 0.3：采样点在这个 texel 内部、离左边界 0.3 格的位置。

场景中的点 p 位置是连续的，所以采样点几乎不会恰好落在格子中心。后面会看到，PCF 能否得到平滑的阴影边缘，关键就在于有没有用上这个小数部分。

2问题：二值比较带来的锯齿

阴影贴图的分辨率有限，通常远低于屏幕在这片区域的像素密度。一个 texel 投到地面上，可能覆盖屏幕上几十个像素。这些像素的采样点都落在同一个 texel 里，查到同一个 z，比较结果完全一样，所以阴影边缘会呈现出 texel 形状的“台阶”。

很自然的想法是“模糊一下”。但模糊什么？这就是 PCF 要回答的问题。

3PCF 的核心思想：过滤“比较结果”，而不是过滤深度

3.1 错误的做法：先模糊深度，再比较

普通颜色纹理可以直接开双线性过滤。如果对深度图也这样做，会得到一个插值后的深度 \tilde z，然后再比较 d_p \le \tilde z。

问题出在遮挡物边缘。深度图记录的是“每条光线碰到的第一个表面”，所以在遮挡物边缘，相邻两个 texel 一个存的是遮挡物的深度（近），另一个存的是旁边地面的深度（远）。下图中光从正上方照下，一块悬空的遮挡物深度为 2，地面深度为 10，地面上的点 p 恰好投影到 texel C 与 D 之间：

从图里可以看出两个问题：

  1. 插值出来的深度没有物理意义。\tilde z = 6 既不是遮挡物的深度，也不是地面的深度，它只是两个无关表面的深度凑出来的数，场景里在这个深度上什么都没有。拿 p 去和一个不存在的表面比较，结论自然也不可靠。
  2. 比较之后仍然是 0 或 1。插值发生在比较之前，而比较会把任何深度值压回 0/1。所以边缘不会变软，只是阴影边界的位置被挪动了。

第 2 点可以再看得具体一些。让 p 沿地面从 C 的中心走到 D 的中心（记位置为 t，t 从 0 变到 1），两种做法得到的可见度 V 如下：

3.2 正确的做法：先比较，再平均

Reeves 等人在 1987 年提出 Percentage-Closer Filtering，翻译过来就是“求更近者所占的百分比”：在采样点周围取一组 texel，每个 texel 单独和 d_p 做一次深度比较，然后对这些 0/1 结果做加权平均：

V(p) = \frac{\displaystyle\sum_i w_i \, H(z_i - d_p)}{\displaystyle\sum_i w_i}, \qquad H(x) = \begin{cases} 1 & x \ge 0 \\ 0 & x < 0 \end{cases}
符号含义
p当前要着色的点
d_pp 到光源的深度，即 p 在光源空间里的 z
i采样点附近参与计算的第 i 个 texel
z_i第 i 个 texel 存的深度，即那条光线碰到的第一个表面的深度
H(z_i - d_p)用第 i 个 texel 做一次普通的阴影判断：z_i \ge d_p 表示光线在到达 p 之前没碰到别的东西，为 1（亮）；z_i < d_p 表示中途被挡住，为 0（暗）。这正是 1.1 节的 \mathrm{lit}(p)，只是换成了第 i 个 texel
w_i第 i 个 texel 的权重，即它在过滤核里占多大分量
V(p)可见度，0 为全暗，1 为全亮

公式可以分三步读：

  1. 逐个比较：H(z_i - d_p) 让每个 texel 各投一票，票面只有 0 或 1。
  2. 加权求和：\sum_i w_i\,H(z_i - d_p) 把票数乘上各自的权重相加。
  3. 归一化：除以 \sum_i w_i，把结果压到 0~1。权重全相等时退化为 V = \dfrac{\text{判为亮的样本数}}{\text{样本总数}}。

结果的含义很直白：周围这片区域里，有百分之多少的 texel 认为 p 是亮的。被平均的是“是否被遮挡”的结论，每个结论本身都有明确含义，所以平均出来的比例才能当作“被照亮的程度”。

比较是非线性操作，过滤是线性操作，两者不能交换顺序。PCF = 先对每个样本做比较，再对比较结果做过滤。

3.3 PCF 得到的“软边”是什么

要注意：PCF 的软边不是物理半影。它的宽度只取决于过滤核的大小（以 texel 为单位），跟光源大小、遮挡物离地面多远都无关。它本质上是抗锯齿：把 texel 的台阶磨平。真实的“离遮挡物越远越虚”需要借助 PCSS 这类可变核宽的方法才能得到。

4交互演示：对比各种过滤方式

下面用一张很低分辨率的阴影贴图（遮挡物是一个斜放的方块和一个圆），在高分辨率画布上重建阴影。每个画布像素都执行一次对应的过滤。

各过滤方式的表现与前文的分析一一对应：

  • 无过滤：每个画布像素只做一次二值比较，同一个 texel 覆盖的像素结果完全相同，边缘呈 texel 形状的台阶。
  • 先双线性深度再比较：插值只改变了深度值，比较后仍是 0 或 1，边缘依旧是硬的，只是边界位置相对无过滤时发生了偏移。
  • 朴素 3×3：边缘出现了中间灰度，但同一个 texel 内的像素取到的是同一组 texel，颜色相同，阶梯仍以 texel 为单位出现，只是由两级变成了多级。
  • 连续核 PCF：权重随采样点的小数部分连续变化，边缘平滑过渡；软边宽度等于核宽，因此 2×2、3×3、5×5 的软边依次变宽，每像素的读取次数也依次增加。
  • 分辨率：texel 越大，同样核宽对应的软边在画布上越宽，台阶也越明显；提高分辨率会让所有方式的边缘都变窄。

5从 2×2 到 N×N：连续平移的核

5.1 最小的 PCF：硬件 2×2

GPU 为此专门提供了比较采样器（HLSL 的 SamplerComparisonState + SampleCmp，GLSL 的 sampler2DShadow）。开启线性过滤时，硬件会取采样点周围 2×2 个 texel，先各自比较，再按双线性权重混合，一条指令就完成了一次 2×2 PCF。

设采样点相对这 2×2 个 texel 中心的小数位置为 (f_x,\ f_y)，四个比较结果按位置排成 \begin{bmatrix} a & b \\ c & d \end{bmatrix}（上行 a, b，下行 c, d），那么：

V = \mathrm{lerp}\big(\mathrm{lerp}(a, b, f_x),\ \mathrm{lerp}(c, d, f_x),\ f_y\big)

2×2 的软边只有 1 个 texel 宽。想要更宽的软边，就得把核做大。

5.2 朴素的 3×3 为什么还有阶梯

最直接的 3×3 PCF 是：把采样点坐标取整，找到它所在的 texel，取这个 texel 和周围 8 个，各自比较后平均。问题出在“取整”这一步。

采样点在 texel 内部滑动。1.3 节说过，采样点坐标是连续的，而 texel 是离散的格子。一个 texel 投到屏幕上往往覆盖很多像素，所以屏幕上相邻的一排像素，对应的采样点在阴影贴图上是一小步一小步往前挪的，前几步都还在同一个格子里：

屏幕像素#1#2#3#4#5#6#7
采样点 u5.15.35.55.75.96.16.3
所在 texel（取整）5555566
朴素 3×3 用到的列4、5、65、6、7

参与的 9 个 texel 完全不变。取整后 5.1 和 5.9 没有区别，小数部分被丢掉了。所以 #1 到 #5 取到的是同一组 texel（二维就是同样的 3 \times 3 = 9 个），每个 texel 权重都是 1/9，算出来的 V 完全相同，屏幕上这 5 个像素颜色一样。

跨过 texel 边界时整组突然换掉。从 #5（u = 5.9）到 #6（u = 6.1），采样点越过了 u = 6 这条格线，取整结果从 5 变成 6，参与的列从 \{4, 5, 6\} 一下子变成 \{5, 6, 7\}：第 4 列整列出去，第 7 列整列进来，V 在这一刻突变。

5.3 解决办法：让核随采样点连续平移

问题的根源是取整丢掉了小数部分，所以解决办法就是把小数部分用起来：把过滤核看成一个宽 3 个 texel 的盒子，盒子中心就是采样点，采样点挪多少盒子就挪多少。每个 texel 的权重等于它被盒子覆盖的长度。

中心在任意位置时，这个盒子会完整覆盖中间 2 个 texel，部分覆盖两边各 1 个 texel。盒子的左右边缘恰好跨过格线的时刻，是采样点位于 texel 中心的时刻，所以小数部分要从 texel 中心开始量：

f = \mathrm{frac}(u - 0.5), \qquad w = [\,1-f,\ 1,\ 1,\ f\,], \qquad \textstyle\sum w = 3

四个权重对应的四列从哪里开始，同样由 u - 0.5 决定：

b = \lfloor u - 0.5 \rfloor, \qquad \text{参与的 4 列} = b-1,\ b,\ b+1,\ b+2

以 u = 5.3 为例：盒子覆盖 [3.8,\ 6.8]，u - 0.5 = 4.8，所以 b = 4、f = 0.8，参与的是第 3、4、5、6 列：第 3 列被覆盖 0.2 = 1-f，第 4、5 列各 1，第 6 列被覆盖 0.8 = f。

对照 5.2 节的朴素 3×3（#1~#5 全是 0.33，#6、#7 突变为 0.67），可以看到三点：

  • 在一组 4 列内部滑动时，列不变，权重在变。#1、#2 用的都是第 3~6 列，但 f 从 0.6 变到 0.8，左端列的权重 1-f 减小，右端列的权重 f 增大；亮的第 6 列占比变大，V 随之增大。朴素做法把小数部分丢掉了，这里则把它变成了两端的权重。
  • 换组发生在 texel 中心，而不是格线上。4 列的起点由 \lfloor u - 0.5 \rfloor 决定，所以换组发生在 u = 5.5（第 5 列的中心），此时盒子的左右边缘正好落在格线 4 和 7 上。
  • 换组的那一刻结果不跳。u \to 5.5^- 时旧组权重趋于 [0,1,1,1]（第 3~6 列），u = 5.5 时新组权重为 [1,1,1,0]（第 4~7 列）：两边真正起作用的都是第 4、5、6 列，各占 1。被移出的列和新移入的列在换组时刻权重都是 0，所以 V 连续。

表中的 V 每一步都增加 0.2/3 \approx 0.067，是一条斜线而不是台阶，这正是 5.2 节交互中橙色曲线的形状。二维时两个方向的权重相乘：

w_{ij} = w_x(i)\, w_y(j), \qquad \sum_{i,j} w_{ij} = 3 \times 3 = 9

一共涉及 4 \times 4 = 16 个 texel，权重总和为 9，所以最后除以 9。可以把它理解为：一个 3×3 texel 大小的方形窗口，中心在采样点上、随采样点连续平移；边缘一圈的 texel 只被窗口覆盖了一部分，就按覆盖比例计权。同理可推广到任意奇数核宽 K：

核宽 K（texel）实际读取 texel一维权重归一化

5.4 Gather：一次取 4 个深度

3×3 连续核要读 16 个深度。普通采样指令一次只返回一个值，就得发 16 次采样。Texture.Gather()（HLSL，DX11 起；GLSL 为 textureGather）一次返回采样位置周围 2×2 共 4 个 texel 的原始值，打包成一个 float4。这 4 个 texel 正是双线性过滤会用到的那 4 个，但 Gather 不做插值，把原值原样交出来。

这一点对 PCF 很重要：PCF 必须先拿到每个 texel 的原始深度，单独比较之后再平均；如果先插值，就又回到了 3.1 节的错误做法。

于是把 4×4 网格切成 4 块 2×2，每块一次 Gather，这就是图 3 中 4 种底色的含义。每块内部 4 个分量的位置如图 4 所示：

需要分清两种“次数”：

步骤3×3 连续核的次数
纹理采样指令（Gather）4
单个深度的比较 H(z_i-d_p)16（每次 Gather 回来的 float4 一次比较 4 个）

现代 GPU 上 float4 运算通常也被拆成标量指令执行，所以比较和累加的运算量并没有减少。真正省下的是纹理采样指令：从 16 次减到 4 次，5×5 核则从 36 次减到 9 次。采样指令要访问纹理缓存，比几次乘加贵得多，这才是用 Gather 的收益。

Gather 返回的 4 个分量不是“从左到右、从上到下”排列的。按 DX11 规范，以纹理 v 轴向下为准：x = 左下，y = 右下，z = 右上，w = 左上。写代码时要按这个顺序把分量拼回行列（见 6.3 节）。

6PCF 的核心代码实现

以下是 HLSL 写法。约定：阴影贴图存的是线性或非线性深度均可，但 d_p 必须和它处于同一空间；深度越大离光源越远（若使用 Reversed-Z，比较方向要反过来）。

6.1 通用 K×K 连续核：点采样 + 手动比较

这一版与第 3、5 节的公式一一对应，最适合对照理解：

// K 为奇数：1、3、5 ...
// uv           : 采样点在阴影贴图上的 UV（0~1）
// receiverDepth: d_p，已减去深度偏移
// mapSize      : 阴影贴图分辨率（texel）
float PCF_KxK(Texture2D<float> ShadowMap, SamplerState PointClamp,
              float2 uv, float receiverDepth, float2 mapSize, int K)
{
    float2 texelPos = uv * mapSize - 0.5;   // 以 texel 中心为整数点：f 从中心开始量
    float2 base     = floor(texelPos);
    float2 f        = texelPos - base;      // 小数部分，决定边缘两列/两行的权重
    int    r        = (K - 1) / 2;

    float sum = 0;
    for (int j = 0; j <= K; ++j)            // 共 K+1 行
    {
        float wy = (j == 0) ? 1 - f.y : (j == K ? f.y : 1);
        for (int i = 0; i <= K; ++i)        // 共 K+1 列
        {
            float wx = (i == 0) ? 1 - f.x : (i == K ? f.x : 1);
            float2 texel  = base + float2(i - r, j - r);                // 第 i 列、第 j 行的 texel 索引
            float  z      = ShadowMap.SampleLevel(PointClamp, (texel + 0.5) / mapSize, 0);
            float  h      = (receiverDepth <= z) ? 1.0 : 0.0;           // H(z_i - d_p)
            sum += wx * wy * h;                                         // w_i · H
        }
    }
    return sum / (K * K);                   // 除以 Σw_i = K×K
}

K = 1 时它就退化为 2×2 双线性 PCF；K = 3 时读 16 个 texel、除以 9。

6.2 硬件比较采样器：一条指令的 2×2 PCF

// 采样器状态：Filter = COMPARISON_MIN_MAG_LINEAR_MIP_POINT
//            ComparisonFunc = LESS_EQUAL   （receiverDepth <= texel 深度 时为 1）
SamplerComparisonState ShadowCmpSampler;

float PCF_2x2_Hardware(Texture2D<float> ShadowMap, float2 uv, float receiverDepth)
{
    // 硬件取 2×2 个 texel，逐个与 receiverDepth 比较，再按双线性权重混合
    return ShadowMap.SampleCmpLevelZero(ShadowCmpSampler, uv, receiverDepth);
}

硬件比较采样器也可以作为更大核的“积木”：在采样点周围按固定偏移调用若干次 SampleCmp 再平均。但它的比较函数只能是硬件支持的几种二值比较，如果想把比较换成别的函数（例如带过渡带的软比较），就只能像 6.1、6.3 那样取原始深度自己比较。

6.3 3×3 连续核的 Gather 版本

float PCF_3x3_Gather(Texture2D<float> ShadowMap, SamplerState PointClamp,
                     float2 uv, float receiverDepth, float2 mapSize)
{
    float2 texelPos = uv * mapSize - 0.5;
    float2 base     = floor(texelPos);
    float2 f        = texelPos - base;

    // 4×4 块覆盖 texel base-1 … base+2。
    // 它的正中心（4 个 2×2 块的公共角点）在 (base + 1) 处，
    // 再用整数偏移把 Gather 位置挪到每个 2×2 块的中心。
    float2 c  = (base + 1.0) / mapSize;
    float4 g0 = ShadowMap.Gather(PointClamp, c, int2(-1, -1));  // 左上 2×2
    float4 g1 = ShadowMap.Gather(PointClamp, c, int2( 1, -1));  // 右上 2×2
    float4 g2 = ShadowMap.Gather(PointClamp, c, int2(-1,  1));  // 左下 2×2
    float4 g3 = ShadowMap.Gather(PointClamp, c, int2( 1,  1));  // 右下 2×2

    // 先比较：step(d, z) = (z >= d) ? 1 : 0，即 H(z - d_p)，一次处理 4 个
    float4 h0 = step(receiverDepth, g0);
    float4 h1 = step(receiverDepth, g1);
    float4 h2 = step(receiverDepth, g2);
    float4 h3 = step(receiverDepth, g3);

    // 再过滤：Gather 分量顺序 x=左下 y=右下 z=右上 w=左上，按行重新拼好
    float4 wx = float4(1 - f.x, 1, 1, f.x);
    float4 wy = float4(1 - f.y, 1, 1, f.y);
    float4 rows;
    rows.x = dot(float4(h0.w, h0.z, h1.w, h1.z), wx);  // 第 0 行
    rows.y = dot(float4(h0.x, h0.y, h1.x, h1.y), wx);  // 第 1 行
    rows.z = dot(float4(h2.w, h2.z, h3.w, h3.z), wx);  // 第 2 行
    rows.w = dot(float4(h2.x, h2.y, h3.x, h3.y), wx);  // 第 3 行
    return dot(rows, wy) / 9.0;                        // 先横向、后纵向：可分离滤波
}

它和 6.1 在 K = 3 时的结果完全相同，只是把 16 次采样压缩成 4 次 Gather。5×5 同理：9 次 Gather 覆盖 6×6 texel，权重换成 [\,1-f,\ 1,\ 1,\ 1,\ 1,\ f\,]，最后除以 25。

6.4 实现要点

  • 深度偏移：d_p 要先减去一个偏移（常数偏移 + 与斜率相关的偏移，或沿法线外推接收点），否则会出现自阴影（shadow acne）。核越大，偏移通常要越大，原因见第 7 节。
  • 未写入的区域：阴影贴图清屏值一般是最远深度，把 d_p 截到略小于它，可以保证贴图中没有画到的区域总是判为亮。
  • 图集与边界：多个阴影共用一张图集时，4×4 或 6×6 的读取范围会越过当前阴影的边界，需要在每个阴影周围留出至少半个核宽的边框。
  • 比较函数可以替换：代码结构是“对每个样本求一个函数值，再加权平均”。把 H 换成带过渡带的斜坡，或换成按遮挡厚度计算的透射率，过滤部分完全不用改。

7PCF 的代价与固有问题

  • 代价随核宽平方增长：3×3 读 16 个 texel，5×5 读 36 个。每个屏幕像素、对每个投影阴影各执行一次。一个像素如果同时被几盏投影灯照到，或者落在级联阴影两级之间的过渡带里，就要做多次 PCF。
  • 半影宽度固定：\text{软边宽度} = \text{核宽} \times \text{texel 的世界尺寸}。阴影贴图分辨率变化（例如级联阴影的远近级联）时，软边宽度也跟着变。
  • 自阴影（shadow acne）加剧：核越大，参与比较的 texel 离采样点越远。对于倾斜的接收面，远处 texel 对应的表面深度和 d_p 差得更多，更容易“自己挡自己”，需要更大的深度偏移。常见对策包括随斜率增大的偏移、按样本离中心的距离增加偏移、接收面平面深度偏移（receiver plane depth bias），以及用软比较代替二值比较。
  • 不能预过滤：因为比较依赖于每个像素自己的 d_p，没法像方差阴影贴图（Variance Shadow Maps）或指数阴影贴图（ESM）那样提前把阴影贴图模糊好或生成 mipmap。

8进阶：PCSS —— 可变核宽的 PCF

PCF 的软边宽度固定。真实阴影里，遮挡物离接收面越远、光源越大，半影越宽。PCSS（Percentage-Closer Soft Shadows，Fernando 2005）的思路是：先估算半影宽度，再用这个宽度做 PCF。

  1. 遮挡物搜索：在一个搜索半径内采样阴影贴图，只统计比接收者更近的样本，求平均遮挡深度 d_{\text{blocker}}。没有遮挡物时直接返回 1。
  2. 估算半影：由相似三角形，
    w_{\text{penumbra}} = \frac{(d_p - d_{\text{blocker}})\cdot w_{\text{light}}}{d_{\text{blocker}}}
    方向光（光源在无穷远）简化为 \tan(\theta/2)\cdot(d_p - d_{\text{blocker}})，\theta 为光源的张角。
  3. PCF：用上一步的宽度作为核半径做 PCF，样本通常改为圆盘上的泊松或低差异序列分布。
PCF 与 PCSS 的关系 PCSS 不是 PCF 的替代品，而是 PCF 的“前置估算器”：最后一步仍然是 PCF，只是核宽由每个像素的遮挡物距离决定，而不是固定的 3 或 5 个 texel。
