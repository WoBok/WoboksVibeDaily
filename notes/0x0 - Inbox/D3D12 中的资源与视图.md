## 基本概念

- Resource 定义数据及其基本形态；View 定义管线如何访问其中一部分
- View 通常描述：范围、格式解释和访问角色，本身不复制数据
- 同一个 Resource 可以创建多个兼容 View
- 切换读写用途时，还必须正确处理 Resource State / Layout、Barrier 和同步
- Sampler 与 SRV 分离：SRV 描述读取什么，Sampler 描述如何采样

## 五种视图

| 视图 | 主要用途 | 特点与限制 |
|---|---|---|
| **RTV** | 写入颜色渲染目标 | 用于光栅化输出，可支持混合；不能作为着色器随机访问接口 |
| **DSV** | 深度/模板测试与写入 | 可利用 Early-Z、Hi-Z、深度压缩；要求兼容的深度/模板格式 |
| **SRV** | 着色器只读访问 | 可查看纹理或 Buffer；纹理采样可使用过滤和 mipmap |
| **UAV** | 着色器随机读写 | 支持随机访问和原子操作；顺序与可见性通常需要 Barrier 显式保证 |
| **CBV** | 着色器只读常量参数 | 容量较小，适合线程间高度一致的频繁读取 |

## API 概念对照

> 以下只是概念对应，并非完全一一等价。

| D3D12 | Vulkan | Metal |
|---|---|---|
| RTV | color attachment | color attachment |
| DSV | depth/stencil attachment | depth/stencil attachment |
| SRV | sampled image / read-only buffer | texture / read-only buffer |
| UAV | storage image / storage buffer | read-write texture / buffer |
| CBV | uniform buffer | constant buffer |

---

> Resource 回答“数据是什么、放在哪里”，View 回答“这次把它当什么用”——取哪一段、按什么格式解释、以什么角色访问。View 是 Resource 的访问说明书：告诉 GPU 访问哪一部分、如何解释，以及在管线中承担什么角色；真正的访问正确性还需要资源状态、Barrier 和同步共同保证。
