Compute Shader · Core mental model

先描述工作，
再让 GPU 排队执行。

Dispatch 决定启动多少个线程组；numthreads 决定每个组包含多少个逻辑线程。GPU 把组分配给 SM，再把组内线程切成 32 线程的 Warp 调度。逻辑线程数从来不等于物理核心数。

总线程= Dispatch(gx, gy, gz)× numthreads(X, Y, Z)

三维只是给工作建立坐标；它不表示 GPU 里真的存在一个三维核心阵列。

01 · Work definition

Dispatch 负责“几组”，numthreads 负责“每组几人”

CPU 和 Shader 各提供一半信息。每个组运行同一份 Shader，可以共享 groupshared 内存并做组内同步；不同组之间没有普通的组内屏障。

CPU / Command list

Dispatch(gx, gy, gz)

创建 gx × gy × gz 个 Thread Group。参数是组数，不是线程数。D3D11/12 每个维度上限为 65,535。

HLSL / Entry point

[numthreads(X, Y, Z)]

编译进 Shader，定义每组 X × Y × Z 个线程。cs_5_0 总数最多 1,024，Z 最多 64。

// 处理 width × height 张量；numthreads 与编译后的 Shader 固定绑定
[numthreads(8, 8, 1)]
void MainCS(uint3 id : SV_DispatchThreadID)
{
    if (id.x >= width || id.y >= height) return; // 向上取整产生的越界线程
    Output[id.xy] = Process(Input[id.xy]);
}

// CPU：组数 = ceil(任务尺寸 / 每组尺寸)
commandList->Dispatch((width + 7) / 8, (height + 7) / 8, 1);

02 · Thread identity

四种 ID 都来自“组坐标 + 组内坐标”

点击上方任意线程即可看到它们同步变化。X 是组内线性化时变化最快的维度。

语义范围 / 公式最常用的场景
SV_GroupID(0..gx-1, 0..gy-1, 0..gz-1)当前 Thread Group 在 Dispatch 网格中的坐标。
SV_GroupThreadID(0..X-1, 0..Y-1, 0..Z-1)当前线程在组内的三维坐标，用于访问 groupshared。
SV_GroupIndexlocal.z·X·Y + local.y·X + local.x把组内坐标压成 0..X·Y·Z-1；归约、共享数组和 Warp 分段都常用。
SV_DispatchThreadIDGroupID · numthreads + GroupThreadID（逐维）整个 Dispatch 中的全局三维坐标，通常直接作为像素、元素或体素索引。

SV_DispatchThreadID 不是“系统给的神秘编号”，只是组坐标乘组尺寸，再加组内坐标。SV_GroupIndex 也只是一条明确的行主序公式。

03 · Hardware mapping

Thread Group 进入 SM，Thread 被切成 Warp

HLSL 的 Thread Group 对应 CUDA 语境中的 Thread Block；下文写 block 时就是指一个线程组。组是驻留与 groupshared 的单位，Warp 才是 NVIDIA 调度指令的单位。

CPUDispatch生成线程组网格
GRIDThread Groups组之间可乱序执行
WORK DIST.送入 SM整组接纳，不拆到多个 SM
RESIDENT占用组资源寄存器、Shared、槽位
SIMTWarp × 32连续线性线程组成 Warp
ISSUEScheduler → Pipe从就绪 Warp 发射指令
CPU 与 Shader 合起来定义完整线程网格

Dispatch 给出组数，numthreads 给出每组尺寸。此时创建的是逻辑工作量，还没有绑定到某个具体 SM 或 CUDA Core。

Warp 是什么

NVIDIA 把一个组的线性线程按 32 个一段形成 Warp。Warp 的一条指令携带最多 32 条 lane 的活动掩码与操作数；分支后，不同路径通常分批执行。尾部不足 32 个线程仍占一个 Warp，未使用 lane 关闭。

Thread 是一份逻辑程序实例；lane 是它在当前 Warp 内的位置 0..31。Lane 不是一颗被永久绑定的 CUDA Core。

Warp 如何驻留与运行

组被 SM 接纳时，所有 Warp 的寄存器和该组的 Shared Memory 都先分配好。Warp 等访存或依赖时仍叫“驻留”；调度器改选另一个就绪 Warp，不需要软件式保存/恢复上下文。

驻留 ≠ 正在执行。一个 SM 可同时驻留很多 Warp，但每拍只从部分就绪 Warp 发射适合当前执行管线的指令。

RTX Blackwell 的 GB202 SM 白皮书画出 4 个调度分区，每个分区有 Warp Scheduler、Dispatch Unit、寄存器片和执行管线。需要芯片层级背景时，可打开 GB202 GPU 交互式架构图。

04 · Residency

Occupancy：SM 上活跃 Warp 占上限的比例

一个 block（线程组）只有同时拿到 block 槽位、Warp 槽位、寄存器和 Shared Memory 才能驻留。允许驻留的组数取四个约束中的最小值。

本文交互按 2026-05 更新的 CUDA Programming Guide 表格采用 CC 12.x 的 24 个 resident blocks / SM；当前 Blackwell Tuning Guide 13.3 仍写 32。实际调优应从设备属性读取 maxBlocksPerMultiProcessor、sharedMemPerMultiprocessor 等值。

Occupancy 不是速度分数。它只表示可用于隐藏延迟的 Warp 数量。达到足够 Occupancy 后，继续提高可能没有收益；访存合并、缓存命中、指令依赖和执行管线吞吐仍可能是真正瓶颈。

05 · Memory access

Memory Coalescing：32 个地址合成尽量少的 Sector

一条 Warp 访存指令形成一个 request，携带最多 32 条活动 lane 的地址。硬件按地址覆盖范围访问一个或多个 32B 对齐 sector；不是“一个 Warp 每次只能访问一个 32B sector”。

Lane

Warp 内的位置 0..31

每条活动 lane 对应一个逻辑线程，并为同一条 load/store 指令提供自己的地址。活动掩码可以让部分 lane 暂时不参与。

Sector

对齐的 32 字节内存块

L1/L2 的 128B cache line 由 4 个 sector 组成。只用 sector 中 4B，也要搬运整个 32B。32 lane 连续读 32 个 float，理想情况是 4 个 sector。

Warp 形状不直接等于访存效率。形状先决定 32 条 lane 对应哪些 (x,y,z)，Shader 的索引公式再把这些坐标变成地址，最后由地址落入多少个 sector 决定合并结果。对齐的 8×8 行主序 float 访问也可能只触及理想的 4 个 sector；转置或大步长访问才会把它扩散到更多 sector。
